In A6, we'll create the AKS cluster and give its kubelet identity permission to pull our image from ACR. 
Azure's current AKS guidance supports --attach-acr for this integration; for ABAC-enabled ACRs, the newer Container 
Registry Repository Reader role is used instead.

We'll also enable OIDC + Microsoft Entra Workload Identity now. We won't use it immediately, but it avoids having to 
retrofit the cluster later when we connect Pods to Azure resources without static credentials. Microsoft recommends 
enabling OIDC and Workload Identity for this pattern.

# A6.8 — Verify the cluster can actually pull our image

We don't need to deploy the application yet.

Create a temporary Pod:

    kubectl run acr-test --image="akspracticeacr26abin.azurecr.io/session-api:v2" --restart=Never

Check:

    kubectl get pods

You want:

    acr-test    Running  or possibly Completed depending on the container behavior.

Now:

    kubectl describe pod acr-test

Look at the Events section.

    The important thing is that you do not see: ErrImagePull or: ImagePullBackOff

If the image was successfully pulled, our ACR → AKS integration works.

# A6.9 — Delete the temporary Pod

kubectl delete pod acr-test
