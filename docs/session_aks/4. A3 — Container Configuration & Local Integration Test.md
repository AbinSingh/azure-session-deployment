Windows
│

│      │
│      └── :6379

└── Docker
       │
       └── FastAPI Container
              │
              │ REDIS_HOST

       host.docker.internal:6379

The important thing is that the Docker image does not contain environment-specific configuration.

The image is: session-api:v1

The container gets configuration when it starts:

REDIS_HOST=host.docker.internal
REDIS_PORT=6379

This distinction becomes very important in AKS.

# 1. Don't put Redis configuration into the Dockerfile

We should not do this:

ENV REDIS_HOST=host.docker.internal

Why?

Because host.docker.internal is specific to our local Docker Desktop environment.

Our eventual environments will be:

Local Docker
    ↓
host.docker.internal

    Azure
        ↓
    Azure Redis hostname

The same image should work in both places.

So:

    Docker Image
        │
        │ same image
        ▼
    ┌───────────────┐
    │ Local         │ → REDIS_HOST=host.docker.internal
    │ AKS           │ → REDIS_HOST=<Azure Redis endpoint>
    └───────────────┘

# 2. Create a local environment file

For development convenience, create:

.env.local

with:

REDIS_HOST=host.docker.internal
REDIS_PORT=6379
REDIS_DB=0

This gives us:

    .env.local
         │
         ▼
    Docker container
         │
         ▼
    FastAPI
         │
         ▼
    Redis
Important

Do not commit .env.local.

Our .dockerignore already excludes .env, but let's also add:

.env.local to .gitignore.

Your .gitignore should contain something like:

    .venv/
    __pycache__/
    .idea/
    .env
    .env.local

# 3. Why .env.local isn't inside the image

This is worth understanding.

We have:

    Docker image
    │
    ├── Python
    ├── FastAPI
    ├── Application code
    └── Dependencies

But not:

    Redis hostname
    Redis password
    Azure endpoint

Those belong to the environment in which the container runs.

This is the beginning of the 12-factor application style of configuration:

Configuration that varies between environments should be supplied externally.

# 4. Run the container using the environment file

Stop the current container with: Ctrl + C

Then run:

docker run --rm -p 8000:8000 --env-file .env.local session-api:v1

Now Docker reads: .env.local and injects:

REDIS_HOST
REDIS_PORT
REDIS_DB

into the container.

# 5. Verify from inside the application

Your existing: GET /redis/config

should return:

{
  "redis_host": "host.docker.internal",
  "redis_port": 6379
}

This is useful for learning.

But remember: we'll remove this endpoint before production because exposing infrastructure configuration through an HTTP endpoint isn't something we want in our final application.

# 11. A subtle but important distinction

At this point we have:

Image and: Container and: Redis

They are three separate concepts.

                   Docker Image
                  session-api:a2
                        │
                        │ docker run
                        ▼
                 FastAPI Container
                        │
                        │ TCP
                        ▼
                 Redis Server

The image is immutable packaging. The container is a running instance.

Redis is an external stateful service. This distinction will become extremely important in AKS.

# 12. What happens in AKS?

Our local experiment:

    FastAPI Container
           │
           ▼
    host.docker.internal
           │
           ▼
    Windows Redis

will eventually become:

    FastAPI Pod
           │
           ▼
    Environment Variable
           │
           ▼
    Azure Redis Endpoint
           │
           ▼
    Managed Redis

And here's the important part: The FastAPI Docker image doesn't change.

Only the environment changes. That's exactly what we want from a deployable application artifact.

# 13. A3 completion checklist

Before committing, verify:

     Dockerfile builds successfully.
     Container starts successfully.
     / works.
     /docs works.
     /redis/ping returns true.
     Login works.
     /profile works.
     Session appears in Redis.
     Container can be stopped.
     Session remains in Redis.
     Container can be restarted.
     Existing session still authenticates.
     Temporary /redis/config endpoint removed.
     .env.local is in .gitignore.
