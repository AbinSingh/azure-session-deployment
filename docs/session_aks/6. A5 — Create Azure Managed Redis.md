# Big picture

We'll now replace:

    FastAPI Container
          │
          ▼
    Windows Redis

with:

    FastAPI Container
          │
          │ TLS
          ▼
    Azure Managed Redis

One current Azure detail matters here: Azure Cache for Redis is being retired, and Azure Managed Redis 
is the recommended service for new deployments. Azure Managed Redis reached GA in 2025, while creation of new 
Azure Cache for Redis Basic/Standard/Premium instances is being phased out. So we'll use Azure Managed Redis, 
not the older Azure Cache for Redis service.

For our learning workload, we'll create a relatively small/dev-oriented configuration and later discuss 
what we'd change for production.

# A5.3 — Create Azure Managed Redis (USE AZURE PORTAL for simplicity)

For this exercise, use the smallest suitable SKU available to your subscription/region.

First inspect the available SKUs/options: az redisenterprise create --help

Then create the resource using the current CLI syntax supported by your installed Azure CLI.

Because Azure Managed Redis SKU names and CLI options can change, don't blindly use an old az redis create command from tutorials—that command targets the retiring Azure Cache for Redis service. Microsoft's current guidance is to use Azure Managed Redis for new deployments.

If your CLI exposes the Balanced_B0/equivalent small managed tier, use the smallest available development SKU.

# A5.6 — Important: TLS

Unlike our local Redis: 127.0.0.1:6379 , we will connect to Azure Redis over TLS.

Conceptually:

    FastAPI Container
          │
          │ TLS
          │
          ▼
    Azure Managed Redis

So our application configuration needs another setting: REDIS_SSL=true

and likely a TLS port rather than the local plain Redis port.

# A5.7 — Update redis_client.py

import os

import redis


REDIS_HOST = os.getenv("REDIS_HOST", "127.0.0.1")
REDIS_PORT = int(os.getenv("REDIS_PORT", "6379"))
REDIS_DB = int(os.getenv("REDIS_DB", "0"))
REDIS_SSL = os.getenv("REDIS_SSL", "false").lower() == "true"

redis_client = redis.Redis(
    host=REDIS_HOST,
    port=REDIS_PORT,
    db=REDIS_DB,
    ssl=REDIS_SSL,
    decode_responses=True
)

Now:

    Local
        REDIS_SSL=false
    Azure
        REDIS_SSL=true
    
    Same Python code.

# A5.9 — Update redis_client.py for authentication

Add:

REDIS_USERNAME = os.getenv("REDIS_USERNAME")
REDIS_PASSWORD = os.getenv("REDIS_PASSWORD")

Then:

redis_client = redis.Redis(
    host=REDIS_HOST,
    port=REDIS_PORT,
    db=REDIS_DB,
    username=REDIS_USERNAME,
    password=REDIS_PASSWORD,
    ssl=REDIS_SSL,
    decode_responses=True
)

So the complete configuration becomes:

import os

import redis


REDIS_HOST = os.getenv("REDIS_HOST", "127.0.0.1")
REDIS_PORT = int(os.getenv("REDIS_PORT", "6379"))
REDIS_DB = int(os.getenv("REDIS_DB", "0"))
REDIS_SSL = os.getenv("REDIS_SSL", "false").lower() == "true"


REDIS_USERNAME = os.getenv("REDIS_USERNAME")
REDIS_PASSWORD = os.getenv("REDIS_PASSWORD")

redis_client = redis.Redis(
    host=REDIS_HOST,
    port=REDIS_PORT,
    db=REDIS_DB,
    username=REDIS_USERNAME,
    password=REDIS_PASSWORD,
    ssl=REDIS_SSL,
    decode_responses=True
)

This remains compatible with local Redis because:

username = None
password = None
ssl = False

# A5.10 — Get the appropriate authentication credentials

For Azure Managed Redis, don't assume the old Azure Cache for Redis access-key workflow applies unchanged. Azure Managed Redis supports Microsoft Entra authentication and Redis access policies; the exact credential path depends on how we configure the resource.

For this exercise, I recommend we use the Azure-supported authentication mechanism exposed by the current resource rather than introducing a permanent static password.

# One important distinction

You now have two different concepts:

Azure CLI
   │
   ├── Core commands
   │     ├── az vm
   │     ├── az network
   │     ├── az storage
   │     └── ...
   │
   └── Extension
         │
         └── redisenterprise
               │
               ├── create
               ├── show
               ├── delete
               └── database

The extension is essentially an additional command module that Azure CLI can load.
