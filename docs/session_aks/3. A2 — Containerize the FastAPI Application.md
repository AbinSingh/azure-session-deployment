# Image vs Container

 This distinction is extremely important.
 
 Image
 session-api:a2 is the package/template.
 
 Think:
 
 Class / executable package
 Container
 
 When we run: docker run ...

 Think: Process created from the image

 So:
 
 Image

   │ docker run

Inside the container, if REDIS_HOST isn't provided, our A1 code defaults to:

127.0.0.1 But now:

Our architecture is:

Windows
│
├── Redis :6379
│

     │

            │

                    │
                    X
               Redis isn't here

This is an excellent failure. It demonstrates why networking changes when we introduce containers.

# Step 9 — Find the host from the container

Because we're using Docker Desktop on Windows, Docker provides a special hostname: host.docker.internal

This lets a container reach services running on the Windows host.

So we'll run the container with:

docker run --rm `
  -p 8000:8000 `
  -e REDIS_HOST=host.docker.internal `
  -e REDIS_PORT=6379 `
  session-api:a2

PowerShell uses the backtick ` for line continuation.

You can also put it on one line:

docker run --rm -p 8000:8000 -e REDIS_HOST=host.docker.internal -e REDIS_PORT=6379 session-api:v1
