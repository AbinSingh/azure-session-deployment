# Big picture

Your current redis_client.py probably has something like:

redis_client = redis.Redis(
    host="127.0.0.1",
    port=6379,
    db=0,
    decode_responses=True
)

This works locally because Redis is running on your Windows machine.

But once FastAPI runs inside AKS:

FastAPI Pod
   │
   └── 127.0.0.1:6379
             │
             ▼
        FastAPI Pod itself

It will not reach Azure Redis. So we're going to separate:

Application code
       +
Configuration

The application will say: "Give me the Redis host."

The environment will decide whether that is: 127.0.0.1 or eventually: <azure-redis-endpoint>

# 1. Update redis_client.py
import os
import redis


REDIS_HOST = os.getenv("REDIS_HOST", "127.0.0.1")
REDIS_PORT = int(os.getenv("REDIS_PORT", "6379"))
REDIS_DB = int(os.getenv("REDIS_DB", "0"))

redis_client = redis.Redis(
    host=REDIS_HOST,
    port=REDIS_PORT,
    db=REDIS_DB,
    decode_responses=True
)

The important part is: os.getenv("REDIS_HOST", "127.0.0.1")

This means:

-- Use REDIS_HOST if it exists; otherwise use 127.0.0.1.

-- So your existing local setup continues working without any extra configuration.

# 2. Why use environment variables?

Think about the same application moving through environments:

                 Same Code
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
     Local        Docker        AKS
       │            │            │
       ▼            ▼            ▼
  127.0.0.1       redis      Azure Redis

We don't want:

if environment == "local":
    ...

elif environment == "aks":
    ...

That would couple your application to its deployment environment.

Instead:

             FastAPI
                │
                ▼
        REDIS_HOST
                │
       ┌────────┼────────┐
       ▼        ▼        ▼
     Local    Docker    Azure

The configuration changes; the application doesn't.

# 5. Let's make the configuration visible

from redis_client import REDIS_HOST, REDIS_PORT

@app.get("/redis/config")
def redis_config():

    return {
        "redis_host": REDIS_HOST,
        "redis_port": REDIS_PORT
    }

# 6. One important distinction: configuration vs secrets
Things like:

REDIS_HOST, REDIS_PORT, REDIS_DB are generally configuration.

But things like:

REDIS_PASSWORD , REDIS_ACCESS_KEY are secrets.

Our eventual AKS architecture will be:

                 AKS
                  │
        ┌─────────┴─────────┐
        │                   │
 Configuration           Secrets
        │                   │
        ▼                   ▼
 Environment          Azure Key Vault
        │                   │
        └─────────┬─────────┘
                  ▼
              FastAPI

# 8. What changed architecturally?

Before A1:

    FastAPI
       │
       │ hard-coded
       ▼
    127.0.0.1:6379

After A1:

    FastAPI
       │
       ▼
    Configuration
       │
       ▼
    REDIS_HOST
       │
       ▼
    127.0.0.1:6379

Later:

    FastAPI
       │
       ▼
    Configuration
       │
       ▼
    REDIS_HOST
       │
       ▼
    Azure Redis

The FastAPI application doesn't need to know that it is running on Azure.

That's exactly what we want.
