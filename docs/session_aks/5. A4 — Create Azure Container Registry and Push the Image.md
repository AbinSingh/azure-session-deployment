# 1. What does az acr login actually do?

az acr login
      │
      ├── authenticate you with Azure
      │
      ├── obtain ACR authentication token
      │
      └── configure Docker credentials

# 2. What does docker tag do?
Before:

session-api:v1
       │
       ▼
   IMAGE ID
   abc123...


After:

session-api:v1
       │
       ├──────────────► IMAGE ID abc123...
       │
       │
akspracticeacr26abin.azurecr.io/session-api:v1
       │
       └──────────────► IMAGE ID abc123...

The azurecr.io name tells Docker:

"When I push this image, the destination registry is this ACR."

Microsoft documents this fully-qualified registry/repository/tag format for Docker push operations.

# 3. Now the important part: docker push
Docker is responsible for the push.

Conceptually:

docker push
    │
    ▼
Docker CLI
    │
    ▼
Docker Engine / daemon
    │
    │  HTTPS
    │
    ▼
akspracticeacr26abin.azurecr.io
    │
    ▼
Azure Container Registry


The Docker client/engine communicates with ACR using the OCI/Docker Registry HTTP API over HTTPS.

So Azure CLI is not sitting in the middle of this communication.

That's a very important distinction.

# 4. Where do OSI layers fit?

Your thinking about OSI is correct.

For the actual image push, you can approximately map it like this:

    OSI layer	What happens during docker push
    L7 Application	Docker/OCI Registry HTTP API
    L6 Presentation	TLS encryption
    L5 Session	HTTPS/TLS session
    L4 Transport	TCP
    L3 Network	IP routing
    L2 Data Link	Ethernet/Wi-Fi
    L1 Physical	Electrical/radio/optical signals

In modern networking, the OSI model is mostly a conceptual model. In practice, people usually describe this as:

    Docker Registry API
           ↓
         HTTPS
           ↓
          TLS
           ↓
          TCP
           ↓
          IP
           ↓
     Ethernet / Wi-Fi

# 5. What protocol does Docker actually use?

This is the interesting part. docker push isn't simply doing: FTP  or SFTP

Instead, Docker communicates with the container registry using the Docker Registry HTTP API / OCI distribution mechanisms, over HTTPS.

For example, conceptually Docker might make requests like:

POST https://akspracticeacr26abin.azurecr.io/v2/session-api/blobs/uploads/

and: PUT https://akspracticeacr26abin.azurecr.io/v2/session-api/manifests/v1

The exact sequence is more complicated because Docker first determines which layers already exist and then uploads missing layers.

# 6. An image isn't sent as one giant file

This is another important concept.

Suppose your image contains:

session-api:v1

    ┌──────────────────────┐
    │ Image manifest       │
    ├──────────────────────┤
    │ Layer 1              │
    ├──────────────────────┤
    │ Layer 2              │
    ├──────────────────────┤
    │ Layer 3              │
    ├──────────────────────┤
    │ Layer 4              │
    └──────────────────────┘

Docker pushes the image's layers/blobs and metadata, rather than treating the image as one ordinary file.

It also checks whether ACR already has particular layers.

**For example:**

Docker                         ACR


"I have layer A"
       ───────────────────────►
                               "Already have it"

"I have layer B"
       ───────────────────────►
                               "Don't have it"

       upload layer B
       ───────────────────────►

"I have layer C"
       ───────────────────────►
                               "Already have it"

That's why you may see output such as:

The push refers to repository [...]

abc123: Pushed
def456: Layer already exists
789abc: Pushed
v1: digest: sha256:...

# 7. Where does authentication fit?

                 AUTHENTICATION
                      │
                      ▼
               Azure CLI (`az`)
                      │
              obtains ACR token
                      │
                      ▼
                Docker config
                      │
                      │
                      ▼
                 docker push
                      │
                      │ HTTPS
                      ▼
                     ACR

So authentication and data transfer are separate concerns.

az acr login

    Responsible for:
    
    Azure authentication
            +
    ACR authentication setup
            +
    Docker credential configuration
    docker push

Responsible for:

    Finding local image
            +
    Talking to registry
            +
    Authenticating using configured credentials
            +
    Uploading layers
            +
    Uploading manifest

Microsoft's documentation specifically notes that after az acr login, credentials are cached and subsequent Docker commands don't require you to provide username/password again.

# 8. So who creates the network connection?

Docker.

More precisely, the Docker client/engine initiates the connection to: akspracticeacr26abin.azurecr.io

and the underlying operating system networking stack handles:

    DNS
     ↓
    IP
     ↓
    TCP
     ↓
    TLS
     ↓
    HTTP

You can think of the responsibility as:

┌─────────────────────────────────────┐
│ Azure CLI                            │
│                                     │
│ "Here is a credential/token that    │
│  Docker can use to access ACR."     │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│ Docker                              │
│                                     │
│ "I'll establish HTTPS connection    │
│  and transfer the image."            │
└──────────────────┬──────────────────┘
                   │
                   ▼
              Internet/network
                   │
                   ▼
┌─────────────────────────────────────┐
│ Azure Container Registry            │
│                                     │
│ Authenticate → authorize → store    │
│ image layers + manifest             │
└─────────────────────────────────────┘

And one subtle but important point: az acr login itself does make network calls to Azure, so it isn't completely "local." But the actual image upload performed by your docker push is Docker-to-ACR communication, not Azure CLI-to-ACR image transfer.
