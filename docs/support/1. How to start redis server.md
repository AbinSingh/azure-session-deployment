
That error means the Memurai client is installed, but nothing is currently listening on 127.0.0.1:6379. Since it worked two weeks ago, the most likely cause is that the Memurai Windows service is stopped or failed to start.

Let's diagnose it on Windows.

# 1. Check whether Memurai is running

Open Command Prompt as Administrator and run:

sc query Memurai

Also try:

sc queryex Memurai

If you see something like:

STATE              : 1  STOPPED  then that's the problem.

Start it with: net start Memurai

Then try:

memurai-cli

# 2. Check whether anything is listening on port 6379

Run:

netstat -ano | findstr :6379

If Memurai is running correctly, you should see something similar to:

TCP    127.0.0.1:6379    0.0.0.0:0    LISTENING    1234

If nothing is returned, there is no process listening on port 6379.

If you get a PID, check what process owns it: tasklist /FI "PID eq 1234"

Replace 1234 with the PID you see.

# 3. Check the Windows Services GUI

Press:

Win + R → services.msc → Enter

Look for a service named something like:

Memurai
Memurai Developer
Memurai Redis

Check its status. If it's Stopped, right-click → Start.

I'd also set Startup type → Automatic if you want Memurai to start whenever Windows boots.

# 4. If the service won't start

This is the important case.

Run:

net start Memurai and tell me the exact error message you get.

You can also check:

Event Viewer → Windows Logs → Application and look for Memurai-related errors.

# 5. Check whether Memurai's port/config changed

If the service is running but 6379 is still unavailable, run:

netstat -ano | findstr LISTENING | findstr 6379

Also check Memurai's configuration. Depending on your installation, the config may be under its installation directory.

You can find where the service executable/config is coming from with:

sc qc Memurai

Look at:BINARY_PATH_NAME

That can reveal whether Memurai is starting with a particular configuration file or a different port.
